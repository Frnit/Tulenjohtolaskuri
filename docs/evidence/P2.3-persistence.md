# P2.3 state and persistence evidence

Change identifier: `CHG-P2-3-PERSISTENCE-001`

## Scope

P2.3 adds a small AppState, a guarded Web Storage adapter, a versioned persistence
repository, and the minimum main/AR bootstrap integration. It does not change the
domain calculations or replace the legacy AR handoff contract.

The service-worker precache adds the three new local runtime scripts so that the
already accepted offline main-page behavior does not regress.

## Accepted behavior

- Valid `tj_targets`, `tj_profs_v2`, and `tj_ar_fov` values migrate independently
  to verified v1 envelopes while the source keys remain unchanged.
- Valid v1 records take precedence over legacy records.
- Malformed JSON, invalid records, failed reads, failed writes, and quota errors are
  isolated to the affected record and shown as a local warning.
- Unknown newer schemas are preserved and are not interpreted as v1.
- An empty target collection is a supported state on both pages; AR does not
  dereference a missing option.
- New writes are read back and validated before AppState adopts them.
- Reset removes only application-owned keys and preserves unrelated origin data.

## Executable evidence

`tests/target/persistence.pw.spec.mjs` covers legacy migration, v1 loading,
corruption isolation, failed reads, empty collections, quota failure, unknown
schemas, verified writes, and reset scope.

`tests/target/persistence-source.node.test.mjs` prevents direct Web Storage calls in
the two application pages and prevents origin-wide `clear()` calls in production
code.

`tests/pwa/current-baseline.pw.spec.mjs` verifies that the new runtime scripts are
preloaded and that the main page still reloads offline under the current service
worker behavior.

## Rollback

Revert `CHG-P2-3-PERSISTENCE-001`. Legacy keys have not been deleted or rewritten by
migration. Records created only in the v1 namespace remain available for a later
compatible release; the pre-P2.3 application does not interpret them.
