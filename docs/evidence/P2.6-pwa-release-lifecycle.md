# P2.6 PWA and release lifecycle

Change identifier: `CHG-P2-6-PWA-LIFECYCLE-001`.

## Accepted decisions

- The main page, AR page, local scripts, manifest, icon and local offline guide
  are the declared offline Core.
- Camera and orientation remain offline-conditional. A fresh geolocation value
  is not promised without network-assisted platform services.
- A completed update waits for an explicit user action. The waiting worker does
  not call `skipWaiting()` during installation.
- User-approved activation notifies all open application tabs and reloads them
  after the controller changes.
- A failed precache deletes only its incomplete cache and leaves the active
  release in use.
- Fetches read only from the active release cache. Activation removes old caches
  only under the application-owned `tjl-core-` prefix.
- A rollback publishes older application code as a new build with a new
  `swBuildId`; storage schemas are never downgraded automatically.

## Release metadata

`src/pwa/release.js` is the runtime source for app, worker, cache, asset and
storage compatibility identifiers. The `next` integration candidate uses
`releaseVersion` `0.3.0-rc.1` and a unique candidate build ID. `commitSha` and
`rollbackTarget` intentionally remain `null` on `next`; a release promotion must
set both to the accepted immutable source and rollback release before merging to
`main`, and must assign a new `swBuildId`.
