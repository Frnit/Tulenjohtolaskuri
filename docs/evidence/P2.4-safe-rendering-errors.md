# P2.4 safe rendering and recoverable errors

Change identifier: `CHG-P2-4-SAFE-UI-001`.

## Accepted behavior

- Stored target and profile names are inserted through DOM text properties. They
  cannot create elements or event handlers.
- Every calculation advances `AppState.inputRevision`. A result records the
  revision it was based on, and outputs are removed when required inputs are no
  longer available.
- An unexpected calculation or UI action failure becomes a structured,
  recoverable application error. The user sees a generic local message, the
  failed result is cleared, and unrelated controls remain usable.
- Error causes are retained only in application state for diagnosis. They are not
  placed in the DOM or written to the console.

## Error shape

Application errors contain `kind`, `code`, `source`, `recoverable`, `field`,
`messageKey`, and `cause`. The stable `code` and `source` may be logged; the
original cause and user inputs are excluded from logs and notices.
