# P2.1 test harness and reproducible software evidence

## Scope and baseline

This harness records software behavior at audited baseline
`797d77ff72d28c5a1e88b82e4155c2d0de93dbd2`. It does not validate domain-calculation
accuracy, physical Android behavior, or operational suitability. Production files
remain unchanged.

Evidence classes are physically separated:

- `tests/characterization`: observed current behavior;
- `tests/defects`: positive assertions for known defect signatures;
- `tests/target`: approved product or harness behavior;
- `tests/browser`: browser-level harness capabilities;
- `tests/pwa`: service-worker and cache characterization;
- `tests/fixtures`: non-production evidence inputs.

## Tooling decision

Selected option A: Node's built-in `node:test` runner plus Playwright. Node handles
source and fixture assertions without another runner or transform layer. Playwright
provides real Chromium DOM, LocalStorage, navigation and service-worker behavior.
The rejected option, Vitest plus Playwright, would duplicate the non-browser runner
and add configuration without a present need in this inline classic-script codebase.

The only npm development dependency is `@playwright/test` `1.63.0` under the
Apache-2.0 license. The lockfile fixes the dependency graph. The application has no
npm or CDN runtime dependency.

## Reproduction

Prerequisites are Node `24.19.x` and pnpm `11.19.0`.

```text
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test
```

The browser commands start a Node HTTP server on `127.0.0.1:4173`, run Chromium,
and close the server in the same controlling process. The server serves repository
files with explicit MIME types and no external network dependency. It is test-only
and does not represent production deployment.

Individual evidence classes can be run with:

```text
pnpm run test:node:characterization
pnpm run test:node:defects
pnpm run test:target
pnpm run test:browser:characterization
pnpm run test:browser:defects
pnpm run test:browser:target
pnpm run test:pwa
```

## Known-defect semantics

Tests containing `@known-defect` and `[KNOWN BASELINE DEFECT]` pass only when the
precise defect signature is reproduced. This is evidence of the defect, not approval
of it. An unrelated failure still fails the test and CI. An approved repair should
make the corresponding defect test fail; that test is then converted into an
accepted target regression test with the approved change identifier.

## PWA capability and limits

The harness now verifies service-worker registration, current cache name and
precache entries, a controlled offline reload of the cached index, and current
cross-cache lookup behavior. The release-fixture directory reserves a place for
later V1-to-V2, failed-precache, waiting-worker, multi-tab and rollback scenarios.
Those scenarios are not claimed by P2.1.

Desktop Chromium results do not establish physical Android, permission, orientation,
installed-PWA or device-sensor compatibility. `DEVICE-RESULTS.md` is an unpopulated
record for future physical testing.

## CI and repository policy

`.github/workflows/p2-1-tests.yml` checks out full Git history and tags so the audited
commit can be inspected by SHA, installs the exact pnpm and lockfile dependencies,
installs Chromium, runs every evidence class separately, and uploads diagnostics only
on failure. It uses no secrets, deployment or release action.

Remote inspection on 2026-09-11 found no branch protection on `main`. No repository
setting was changed. Recommended future rules are: disallow force pushes and deletion,
require a pull request, and require this evidence workflow before merge.
